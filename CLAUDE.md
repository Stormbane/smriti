## What smriti is

smriti gives one AI agent persistent memory and a continuous self across sessions and harnesses (Claude Code, Codex).
The memory is a tree of plain markdown files on local disk (`$SMRITI_ROOT`, default `~/.narada`), searched through a local SQLite index; the nightly sends each day's log to an LLM CLI, and backups push to a git remote you choose.
It grew inside one setup (the entity Narada and its user Suti, the maintainer) and is being generalised: alpha, Windows-first, one maintainer, no CI.

## Status

**Live** (runs daily in the reference install):
- `smriti write`, `smriti read`, and the MCP server (`python -m smriti.mcp_server`): dated markdown writes, and hybrid search (0.5 vector + 0.3 keyword + 0.2 trunk distance; the CLI also reranks, the MCP path doesn't).
- Day-log capture: `smriti logd` merges Claude Code transcripts, Codex rollouts and voice transcripts into `log/YYYY/MM/DD.jsonl` (`src/smriti/daylog/`).
- `smriti nightly` (03:00): reconcile → render → digest (one `claude -p` call per day, `codex exec` as fallback) → week/month/year rollups → index → witness (a git commit plus an OpenTimestamps stamp) → status file.
- `smriti morning` (07:00): one message a day composed from the digest. Its persona is hard-coded to the reference user.
- The wake briefing: a SessionStart hook prints `smriti.wake.briefing()`, at most 9,500 characters.
- Backups: `<root>/.smriti/backup.py` commits and pushes the memory tree at each wake and in the nightly.

**Parked** (the code is present but doesn't run; removal is plan 4.0 and 6.4): `smriti sleep --deep` (cascade, JUDGE, ingest, consolidate); the task queue (`smriti queue`, `smriti daemon`, `smriti watch`), which writes stopped feeding on 2026-11-04; `smriti ingest`; `smriti merge-concepts`.

**Legacy:**
- qmd as a recall backend (`smriti recall index`, `smriti recall daemon`); smriti's own index is the default.
- The Hermes harness (`--harness hermes`).
- The PreCompact staging hook.
- The PostToolUse ambient-recall hook: `scripts/install.py` still installs it, but it is off in the reference install and being retired (plan 2.4).

**Personal coupling**, being extracted (plan 6.3):
- the MCP tools `tell_suti`, `smriti_ask_suti`, `smriti_propose_goal_shift` and `smriti_resolve_outbox`;
- the wake's `SUTI NOW` and `ACROSS SURFACES` sections;
- the morning persona;
- the UTC+10 default day boundary (`SMRITI_DAY_UTC_OFFSET`).

## Dev commands

```bash
pip install -e ".[read,dev]"                      # editable install: the installer reads templates from the checkout
python -m pytest -q --ignore=tests/test_perf.py   # perf guards are marked slow and excluded by default
ruff check <files>                                # line length 100
mypy <files>                                      # strict
python scripts/doc_facts.py --write               # refresh the generated counts in README.md, CLAUDE.md, AGENTS.md
smriti status                                     # index and day-log health for $SMRITI_ROOT
```

Tests import `smriti` from wherever it is installed. In a second checkout or worktree, set `PYTHONPATH=src` so they exercise that checkout.

## Rules

- Python 3.11+. `ruff` (line length 100) and `mypy --strict` are the standard. `ruff check src tests scripts` passes (since 2026-11-04); `mypy --strict` doesn't yet (about 209 errors), so keep new and touched code clean.
- No runtime dependencies in the base install (`dependencies = []`). Optional ones go in extras: `read`, `api`, `codex`, `private`, `witness`, `dev`.
- Check `.ai/knowledge/conventions.md` before introducing a new pattern.
- Atomic commits: one logical change per commit.
- The repo is public. No personal data in code, tests, fixtures or docs; use synthetic names (the agent Ari, the user Sam). Private audit reports go in `docs/audits/`, which is gitignored.
- Tests never touch the real memory tree.
